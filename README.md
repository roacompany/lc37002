# PDF → PPT 변환기

PDF를 PowerPoint(.pptx)로 변환하는 웹사이트입니다. 변환은 모두 브라우저 안에서 이루어지므로 파일이 서버로 업로드되지 않고, 별도 백엔드 없이 정적 호스팅(GitHub Pages 등)만으로 운영할 수 있습니다.

## 변환 방식

| 방식 | 결과 | 용도 |
| --- | --- | --- |
| **편집 가능** (기본) | 텍스트와 단순한 도형은 PowerPoint 텍스트 상자·도형으로 바꾸고, 나머지(사진, 그라데이션, 복잡한 그래픽)는 배경 이미지로 둠 | 문구·도형 수정이 필요한 경우 |
| **원본 그대로** | 각 페이지를 고해상도 이미지 한 장으로 넣음 | 모양이 100% 같아야 하는 경우 |

편집 가능 모드의 동작 원리:

1. pdf.js로 페이지를 한 번 렌더링하면서 캔버스에 그려지는 글자 하나하나의 위치와 색을 기록합니다.
2. `getTextContent()`로 얻은 정확한 유니코드 텍스트와 1의 글자 위치를 맞춰, 줄 단위 텍스트 상자와 색·글꼴별 구간(run)으로 묶습니다. 같은 색 윤곽선을 겹쳐 그려 굵게 만든 글자(가짜 굵게)는 굵게 서식으로 바꿉니다.
3. 같은 렌더링에서 벡터 도형의 경로·색·선 두께·점선·투명도와 그리는 순서를 기록해 PowerPoint 도형으로 바꿀 수 있는 것을 고릅니다(아래 "도형 변환").
4. 텍스트 상자·도형으로 옮긴 것만 빼고 페이지를 다시 렌더링해 배경 이미지를 만듭니다. 사진·그라데이션·복잡한 그래픽은 배경에 그대로 남습니다.
5. 글자 위치를 원본에 맞추고(아래 "글자 위치 맞추기"), PDF의 웹 링크는 슬라이드 하이퍼링크로 옮깁니다.

## 글자 위치 맞추기

PDF에 내장된 글꼴은 PPTX에 넣을 수 없어서, PowerPoint는 같은 이름의 설치된 글꼴이나 대체 글꼴로 글자를 그립니다. 글꼴이 바뀌어도 글자가 원래 자리에 오도록 다음과 같이 배치합니다.

- **단어 단위 자간**: 단어와 띄어쓰기를 각각 별도 구간(run)으로 나누고, 구간마다 자간을 따로 정해 다음 단어가 원본 글자의 시작 위치에서 시작하게 합니다.
- **세로 위치**: 텍스트 상자의 첫 줄 기준선은 글꼴과 관계없이 상자 위쪽에서 글자 크기만큼 아래에 놓이므로(LibreOffice로 측정), 이 규칙으로 상자 위치를 정합니다. PDF 글꼴의 높이 정보는 쓰지 않습니다.
- 글자 폭은 변환하는 브라우저의 글꼴로 잽니다. 그래서 변환할 때와 같은 글꼴로 PowerPoint가 글자를 그리면(같은 PC에서 변환하고 여는 경우 등) 글자 위치가 원본과 거의 같고, 글꼴이 다르면 폭 차이만큼 줄 뒤쪽으로 갈수록 조금씩 밀립니다.

## 도형 변환

편집 가능 모드에서 "도형 변환"을 켜면(기본) PDF의 벡터 도형을 PowerPoint 도형으로 바꿉니다.

| PDF 모양 | PowerPoint 도형 |
| --- | --- |
| 축에 맞춘 사각형 (표 테두리, 배경 박스 등) | 사각형 |
| 모서리가 둥근 사각형 | 둥근 사각형 (반지름 유지) |
| 원·타원 | 타원 |
| 직선 | 선 (점선 유지) |
| 다각형, 별, 베지어 곡선, 점선 조각 등 | 사용자 지정 도형 (꼭짓점·곡선 편집 가능) |

- 채우기색, 윤곽선 색·두께, 점선, 투명도를 유지합니다.
- 원과 둥근 모서리는 PDF 생성기마다 곡선을 나누는 방식이 달라서, 경로 위의 점이 타원·둥근 사각형 위에 있는지 기하학적으로 맞춰 봅니다.
- **겹침 순서 보호**: 도형은 배경 이미지 위에 올라가므로, 나중에 그려져 이미지에 남는 것(사진, 그라데이션, 복잡한 경로, 회전된 글자 등)과 겹치는 도형은 옮기지 않고 이미지에 남깁니다. 그래서 사진 아래에 깔린 도형이 사진을 가리는 일이 없습니다.
- 잘림(clip) 영역에 걸린 도형, 그라데이션·패턴 채우기, 페이지 전체를 덮는 배경, 구멍 뚫린 모양(겹치는 여러 조각), 너무 복잡한 경로는 이미지로 남깁니다. 도형이 1500개를 넘는 페이지(복잡한 차트·도면)는 통째로 이미지로 둡니다.

## 글자 인식 (OCR)

스캔한 PDF처럼 글자가 이미지로만 들어 있는 경우 [tesseract.js](https://github.com/naptha/tesseract.js)(WASM)로 한국어·영어를 인식해 편집 가능한 텍스트로 바꿉니다. 엔진과 학습 데이터도 같은 사이트에서 내려받으므로 OCR 중에도 파일이 외부로 전송되지 않습니다. 처음 OCR을 쓸 때 약 8MB를 내려받고, 이후에는 브라우저에 캐시됩니다.

| 옵션 | 동작 |
| --- | --- |
| 스캔 페이지만 (기본) | PDF 텍스트가 없는 페이지에만 OCR 실행 |
| 모든 페이지 | 모든 페이지에서, PDF 텍스트를 지운 배경 이미지 속 글자(사진·캡처 이미지 속 글자 등)까지 인식 |
| 사용 안 함 | OCR을 하지 않음 |

- OCR은 PDF 텍스트를 이미 지운 배경에 대해 실행하므로 같은 글자가 두 번 들어가지 않습니다.
- 300dpi로 다시 렌더링하고 회색조로 바꾼 뒤, 흩어진 텍스트에 강한 SPARSE_TEXT 모드로 인식합니다.
- 글자 크기·기준선은 단어 상자 높이로 추정하고(한글 음절 ≈ 0.9em 등 실측 비율), 글자색과 배경색은 픽셀에서 직접 구합니다. 인식한 자리는 주변 배경색으로 지웁니다.
- 띄어쓰기로 나뉜 단어 묶음마다 시작·끝 위치를 스캔 이미지 속 글자에 맞춥니다.
- 표 테두리를 `|`, `[`로 잘못 읽은 것은 걸러내고 그 자리에서 텍스트 상자를 나눠 칸별 위치를 유지합니다.
- 잘못 읽은 글자가 텍스트로 들어가지 않도록 단어마다 확인합니다. 다음 경우는 텍스트로 바꾸지 않고 지우지도 않아서, 배경 이미지에 원래 모습 그대로 남습니다.
  - 인식 신뢰도가 75 미만인 단어
  - 글자·숫자가 하나도 없는 단어, 홀로 떨어진 한글 자모(ㄱ, ㅏ 등)나 전각 기호가 섞인 단어
  - 신뢰도 90 미만인 영문 한 글자(글머리표·아이콘을 잘못 읽은 경우가 많음)
  - 띄어쓰기 없이 붙은 단어 묶음 중 하나라도 위 조건에 걸린 묶음 전체
  - 인식한 글자를 그렸을 때의 폭이 스캔 속 실제 글자 폭의 0.75~1.5배를 벗어나는 묶음(다른 글자로 잘못 읽었거나 그림을 글자로 읽은 경우)

## 한계

- 도형은 개별 도형으로만 바뀌며, 표는 PowerPoint 표가 아니라 선·사각형과 텍스트 상자로, 차트는 차트 개체가 아니라 도형 묶음이나 이미지로 들어갑니다.
- 원래 도형보다 먼저 그려진 텍스트가 도형에 가려져 있던 경우에도, 변환 후에는 텍스트가 도형 위에 보입니다.
- 회전된 텍스트, 세로쓰기, Type3 글꼴, 윤곽선만 있는 텍스트는 편집 가능한 텍스트로 바꾸지 않고 배경 이미지에 그대로 남깁니다.
- OCR 결과는 100% 정확하지 않습니다(예: `Q3` → `03`). 신뢰도가 낮은 부분은 이미지로 남지만, 잘못 읽은 글자가 텍스트로 들어갈 수 있습니다. 기울어진 스캔, 손글씨, 한국어·영어 외 언어는 인식률이 낮습니다.
- OCR로 지운 자리는 단색으로 채우므로, 사진이나 그라데이션 위의 글자는 지운 흔적이 보일 수 있습니다.
- PDF에 내장된 글꼴은 PPTX에 넣을 수 없습니다. 같은 이름의 글꼴이 PowerPoint를 여는 PC에 없으면 비슷한 기본 글꼴(맑은 고딕, Arial, Times New Roman, Courier New)로 바뀝니다.
- LibreOffice Impress는 PowerPoint와 달리 한글과 영문·숫자 사이에 간격을 더 넣고, 작은 글자를 변환할 때 잰 폭보다 조금 좁게 그립니다. 그래서 LibreOffice로 열면 그 부분이 원본과 조금 어긋나 보일 수 있습니다.
- 암호가 걸린 PDF는 지원하지 않습니다.

## 개발

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/ 에 정적 파일 생성
npm run preview  # 빌드 결과 확인
```

`npm run dev`/`build` 전에 런타임 파일이 자동 복사됩니다: pdf.js의 CMap(한글 등 CJK 글꼴용)·표준 글꼴·WASM 디코더는 `public/pdfjs/`로, OCR 엔진·한국어/영어 학습 데이터는 `public/tesseract/`로.

## 배포

- **Cloudflare Workers**: Cloudflare 대시보드에서 저장소를 연결하고 Build command `npm run build`, Deploy command `npx wrangler deploy`로 설정합니다. 배포 설정은 `wrangler.jsonc`에 있으며 `dist/`를 정적 사이트로 서비스합니다. Worker 이름은 `wrangler.jsonc`의 `name`(`lc37002`)과 같아야 합니다.
- **GitHub Pages**: `main` 브랜치에 push하면 `.github/workflows/deploy.yml`이 배포합니다. 저장소 **Settings → Pages → Source**를 **GitHub Actions**로 설정해야 하며, 무료 요금제에서는 공개 저장소만 가능합니다.

## 구조

- `src/converter.js` — PDF 렌더링, 텍스트 추출·병합, PPTX 생성
- `src/shapes.js` — 경로 기록(Path2D), 도형 분류(사각형·둥근 사각형·타원·선·사용자 지정), 겹침 순서·잘림 검사, PowerPoint 도형 생성
- `src/ocr.js` — OCR 실행, 잘못 읽은 단어 걸러내기, 줄·색 구간 구성, 글자 크기 추정, 인식한 글자 지우기
- `src/fonts.js` — PDF 글꼴 이름을 PowerPoint 글꼴로 매핑, 설치 여부 확인, 텍스트 폭 측정
- `src/main.js` — 업로드·옵션·진행률 UI
